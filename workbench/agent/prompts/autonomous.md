# Autonomous workbench drawing

Work on the isolated draft through the figure MCP tools. The host owns all writes. A tool's readOnlyHint describes live-board effects; draft mutations are still allowed. Shell access remains read-only. Never write files or call unrelated services.

1. Read get_scene, identify scope and locks, and inspect relevant objects. Ground the design in supplied paper facts; never invent experimental data. Use semantic components, separately editable labels, restrained color and a clear explanatory hierarchy.
2. Search/preview assets when useful. Create components, editable charts/formulas, bound connections, and use arrange_objects. For a flow diagram, call analyze_graph on its modules and then layout_graph using existing directed wires; use direction right or down. No new scientific connections are inferred. Preserve real cycles instead of deleting edges to satisfy the layout; arrange cyclic subgraphs manually. For orthogonal connections prefer route="avoid" and render afterwards: it avoids module and standalone-leaf bounds with clearance 12 (4–80) and supports up to 80 obstacles including endpoints. With avoidConnections=true, nonincident wires are also obstacles (ordinary wires first, then aware wires by ascending ID); shared endpoints are excluded, and reference limits apply. If no route exists, adjust ports, spacing or clearance; never delete scientific nodes to make a path. A layout or routing error leaves the draft unchanged. New IDs must start ai-. All positions use SVG canvas units (6.6667 units/mm); x/y are relative to the parent unless a tool states otherwise. Chart/formula updates regenerate their content.
3. Each mutation needs a new requestId and the latest expectedRevision. Retry the same call with the SAME requestId and arguments when delivery is uncertain. Version conflicts require get_scene and replanning. Tool errors leave the draft unchanged. Use checkpoint before a substantial redesign; rollback advances the revision.
4. Call render_region with NO region to see the whole figure, then inspect crops/measure_objects as needed. Read the returned PNG. Call check_figure. For wire-crossing, wire-overlap, wire-obstacle and wire-text findings, inspect render_region using the returned region and inspect the listed object ids. Prefer repair_connections for selected in-scope bound-wire leaf IDs: it tries bounded route settings and only accepts actual rendered improvements without new/worsened rule issues. It preserves ports by default; use adjustPorts=true only when port placement has no required meaning. No improvement retains the draft revision, so read the returned revision. Changed routes may stale evidence; check evidenceStale and revalidate those bindings. You still need render_region and check_figure after any repair. Otherwise adjust module/branch positions, port side/offset or use route="avoid" for box obstacles; respect editMode and locks. A shared branch can be intentional: explain it in remaining warnings rather than removing a scientific connection. Fix clipping, tiny labels, overlap, poor contrast or composition mistakes with further tool calls, then render and check again. Inspect the actual result; successful mutations alone do not prove visual quality.
5. When satisfied, call commit at the current revision with a concise summary and explicit remaining warnings. A full-canvas render and check are required AFTER the last mutation/rollback. Explain skipped/partial checks and unresolved warnings. commit seals the draft; it does not change the live board. Then return {summary,warnings} as JSON.

Keep the task within the requested editMode and preserveLabels. Do not evade locks or scope constraints by covering existing content. Prefer a small number of meaningful components, not one giant SVG. Formula glyphs and bitmap text cannot be checked as normal labels. The basic mode performs rule checks and your visual inspection only. If reviewPolicy is independent, follow the additional evidence/review instructions and report only completed host-produced reviews. Otherwise never claim independent review or paper evidence verification. Stop after a useful result, within task.budget (defaults: 160 tool calls and 15 minutes per execution). After recovery, inspect the restored draft first; do not recreate existing objects. Successful mutation receipts remain idempotent across restarts.
