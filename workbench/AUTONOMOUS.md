# 自主绘图：阶段 1 / 2 / 3 / 4 / 5 / 6 / 7

## 使用

打开「生成图片」或「修改选区」，将「执行方式」改成 **自主绘图 · 观察与修订**，填写正文或修改要求后提交。默认仍是快速编辑。自主模式默认开启「论文证据与独立评审」，也可关闭后使用阶段 1 / 2 的基本闭环。

Agent 在独立草稿内工作，可以检索素材、绘制、观察预览、检查、修订及回滚。运行记录显示工具名称和草稿版本。完成后可以查看前后对比和规则检查，再应用到画板。应用是一项可撤销操作；图表、公式、连接及素材来源信息会保留。

网页版通过 `playwright-core` 使用本机 Microsoft Edge。其他 Chromium 安装可用 `FIGURE_BROWSER_PATH` 指定可执行文件。桌面版直接使用内置 Electron 浏览器，无需另装浏览器。模型接口须支持 Codex SDK 使用的 Responses 工具调用及图片输入。

## 已完成范围

### 阶段 1：可观察、可修订的草稿闭环

- `editor-commands.js`：原子编辑命令和最终差异校验，供画板及 Agent 共用。组件插入、图表/公式创建、绑定连接、对齐排版接入此层；已有图表/公式的手工细节编辑继续保留原来的变换。
- `agent/draft-session.mjs`：隔离场景、递增 revision、requestId 去重、串行命令、8 个持久检查点、回滚、执行日志。写入失败会还原内存事务。草稿可临时包含待修复的越界内容，提交时必须通过检查。
- `agent/browser-runtime.mjs` 与 `agent-runtime.*`：浏览器真实文字/几何测量；浏览器把 SVG 栅格化为 PNG，支持整图和局部观察。复用素材目录、MathJax 和规则检查代码。
- `agent/mcp-stdio.mjs` / `tool-host.mjs`：每任务独立、只监听本机、带随机凭证的工具服务。通过 SDK 的 `mcp_servers.figure` 注册；Codex 文件沙箱继续只读，工具只改本次草稿。
- `commit` 必须在最后一次修改后完成整图渲染和检查。新增或加重的越界错误、检查截断会阻止提交；其他警告需要明确说明。同一问题变严重也会被识别。
- 采纳时再次验证范围、锁定、标签保护和关联连线。自主模式观察了全图，因此运行期间任何画板内容变更都会阻止直接采纳；快速编辑仍允许保留无关区域的手工修改。

### 阶段 2：工作台原生工具

| 能力 | 工具 |
| --- | --- |
| 场景和对象属性 | `get_scene`（分页，可按 ID 查询及包含 SVG） |
| 本地模板、基础要素、论文组件和外部图标 | `search_assets`、`preview_asset`、`insert_asset` |
| 可编辑组件与图元 | `create_component`、`apply_ops`、`remove_objects` |
| 数据图表 | `save_chart`（保存 CSV、系列及出版参数） |
| TeX 公式 | `save_equation`（保存 TeX、字号和颜色） |
| 绑定模块接口的连线 | `connect_objects`（直线/折线/自动避障，端点跟随模块） |
| 对齐、等距分布、固定间距网格 | `arrange_objects` |
| 分支与汇合流程分析及排版 | `analyze_graph`、`layout_graph` |
| 批量尝试修复绑定连线 | `repair_connections`（默认保留端口，复查后才应用） |
| 图表来源数据核验 | `check_evidence`（配合 `bind_evidence.data`） |
| 观察和测量 | `render_region`、`measure_objects`、`check_figure` |
| 草稿版本控制 | `checkpoint`、`rollback`、`commit` |

坐标是 SVG 用户单位，约 6.6667 单位 = 1 mm；位置通常相对父容器，网格排版位置相对画板。新对象 ID 用 `ai-` 前缀。每次变更传入最新 `expectedRevision` 与唯一 `requestId`；不确定请求是否成功时，用相同 ID 和相同参数重试。

更新图表和公式会重新生成其数据内容，同时保留已有内容节点 ID、位置、缩放、外观与 SVG 外层变换；旧 textOverride 不会覆盖新数据。绑定连接的 `label` 是关系元数据，可见说明应另建文字图元。素材保留来源信息；素材示意不代表论文事实。图表只使用用户提供的数值。

### 阶段 3：证据映射与独立评审

- `evidence-contract.js` 把提交的论文正文和当前要求拆成稳定来源片段，保留原文字符位置。`get_evidence` 支持分页、检索和按来源 ID 读取；`bind_evidence` 为模块、关系、数据、公式及选中图元保存具体含义、原文引用和分类。
- 分类为「有资料依据」「示意」「待确认」。引用必须逐字匹配真实片段；重复引文必须给出位置。**逐字匹配只验证可追溯性，不证明原文支持图中的解释**；科学评审会进一步检查含义、数值、单位和箭头方向。模板出处不算论文事实依据。
- 修改对象内容会让对应证据过期；普通几何调整保留证据，但会让之前的评审过期。缺失、过期或待确认的证据阻止送审和提交。检查点包含证据绑定，回滚后必须重新评审。
- `review_figure` 固定当前图稿、PNG、实测几何、规则检查、原文和证据，启动四个独立 Codex 会话：**科学含义与证据、信息组织与表达、视觉与可读性、结构与可编辑性**。每个会话使用单独目录和 Codex home，没有绘图 MCP、设计对话或其他评审意见，仅有只读权限。
- 评审异步执行，`get_review` 可等待最多 10 秒后读取。默认最多 3 轮，每轮最多 2 个评审同时运行，每个评审限 120 秒；受本次任务执行时间预算约束。失败/超时不视为通过；同一快照重试只重新调用未完成角色，已完成意见会复用，重试仍消耗一轮。
- 报告列出具体对象、来源、阻断问题、提醒、修改建议和检查边界。设计 Agent 修订后更新证据，再渲染、检查并发起新一轮评审。仅当前版本的四项评审全部完成且没有阻断问题时，`commit` 才可提交；不能修改已有评审结论。
- 任务结果展示证据原文、上下文、对象定位和每轮报告。采纳后报告与图稿一起保存、撤销、重做和备份。通过「文件 → 独立评审与证据」查看；后续图稿/正文变化会显示历史报告提示。运行期间正文变化也会阻止旧结果采纳。
- 仅评审、没有图元变化的结果也可采纳，把审查记录保存到画板。快速模式不运行独立评审。

独立性来自隔离的会话和职责，四个会话仍使用用户配置的同一模型，可能存在共同盲点。此功能不等同于人工审稿或外部 skill 的完整工作流，不保证科学结论正确。示意数据必须清楚说明；扫描 PDF/OCR 与论文图表自动取证尚未实现；真实模型质量验收需通过阶段 4 的评测入口实际运行并人工确认。

### 阶段 4：恢复、导出验收与质量评测

- 主窗口和副窗口关闭前都会等待存储完成，保存失败时允许返回备份。
- 自主任务失败、取消或服务重启后，可在原任务中点击 **从草稿继续**。恢复当前草稿、证据、检查点、命令回执和评审记录；同一命令不会重复执行。设计 Agent 使用新会话读取恢复后的草稿，不恢复此前的隐藏推理或对话上下文。画板/正文已变化时禁止直接继续，需提交新任务。
- 每位评审完成后即原子保存报告。相同快照复用已完成角色；画稿或证据变化后重新评审。评审轮数跨恢复累计，已耗尽轮数时需查看报告并提交新任务。
- 密集图稿送审时增加四张重叠局部高清 PNG（每张最长边 2200 像素）。所有图稿实际导出 SVG、PDF，再把 PDF 栅格化为预览，连同尺寸、文本提取结果送给评审员。导出失败由宿主阻断通过。评审目录保存原始导出文件与图像；这不等同于自动证明两种渲染完全一致。
- 「任务预算」支持 2–30 分钟、20–400 次工具调用、1–3 轮评审。时间与调用次数按每次执行计算，手动继续重新获得该额度；评审轮数按原任务累计。展示设计与评审的已报告 token 总量，不换算或承诺费用上限。
- `agent/evaluation-cases.mjs` 固定四个**合成**验收任务：流程图、双分支融合、数据图表、局部修改。自动检查可见标签、绑定方向、原始数据、锁定对象与提交条件；人工评审字段保持 pending，不能用模型自评代替人工验收。

#### 运行质量评测

在 workbench 目录执行：

```powershell
npm run eval:prepare
# 配置并启动工作台服务后，以下命令会实际调用已配置模型并产生用量。
npm run eval:live -- --case pipeline --repeat 1
npm run eval:live -- --case all --repeat 3
```

可用 `--origin http://127.0.0.1:端口` 指定本机服务，`--out 目录` 指定输出。准备模式不调用模型；live 模式不采纳结果到用户画板，保存报告与 SVG/PNG 到 `evaluation-results/`。报告分开记录自动检查、耗时、token、评审轮数和人工验收。固定任务便于比较不同版本，但尚不是覆盖真实论文的质量基准。

### 阶段 5：图表数据核验与流程排版

**图表数据核验**

- `bind_evidence` 可把图表绑定到原文中的完整 CSV、TSV 或简单 Markdown 表格。`data` 指定引用序号，以及可选的原表行、列索引；默认使用全表。引用仍必须逐字匹配原文，不能把 Agent 自己整理的数据冒充原文表格。
- `check_evidence` 对照可编辑图表的数据、表头和误差列，返回不一致的行列、期望值和实际值；采用十进制规范化比较，避免浮点舍入掩盖精确值的变化。分类标签和表头保持文字一致，数值允许等值写法，例如 `1.20` 与 `12e-1`。
- 有依据的图表必须提供数据映射。数据不一致、映射无效或缺少映射会阻止独立送审和提交；工作台采纳时再次核验。
- 只有自然语言数值、没有完整表格时，可明确填写 `data.kind=unstructured` 和原因。它始终显示为「未逐值核验」，需要模型核对并在提交中披露；即使勾选自动应用，也会保留预览供用户核对后应用。不能用来绕过原文中已有表格的差异。
- 当前引用片段最长 1800 字符；跨片段的大表、OCR、计算派生数值、单位换算和复杂 Markdown 单元格尚未自动核验。表格值一致也不证明科学含义、轴标签别名或绘制标记正确。
- 结果面板显示逐值核验统计和原表行列，随证据、检查点、撤销和项目保存。新评审记录使用 schema 2；旧 schema 1 记录仍可读取。

示例（原文引用包含完整表头和数据行）：

```json
{
  "objectId": "ai-chart",
  "claim": "原表中的两组测量值",
  "classification": "supported",
  "rationale": "",
  "citations": [{"sourceId": "paper-0001", "quote": "Case,Time (ms)\nA,12\nB,18"}],
  "data": {"kind": "table", "format": "csv", "citationIndex": 0}
}
```

**流程分析与排版**

- `analyze_graph` 读取所选模块已有的绑定连线，返回入口、出口、前后关系、分层、断开的子图、外部连接及被循环阻塞的节点。
- `layout_graph` 根据已有方向将模块从左向右或从上向下排列，使分支并排、汇合后继续。支持最多 80 个互不包含的模块，`gap`/`laneGap` 控制层间与分支间距，`x`/`y` 为画板坐标。
- 保留组件尺寸、文字、数据、端口与连线方向；连线几何跟随移动。纯位置变化保留关系证据，但此前评审仍会因草稿版本变化而失效。
- 遇到循环、锁定对象、越界或覆盖未选模块时整体拒绝，不留下部分修改。真实反馈环应保留并手动排版，不能为通过排版而删除科学关系。
- 此阶段不新增科学连接，不提供文字自动换行；排版后仍须查看渲染和规则检查。

**连线自动避障**

- `connect_objects` 的 `connection.route` 新增 `"avoid"`，使用正交路径绕开其他模块及独立图元的边界。`clearance` 留白为 4–80 个画板单位，默认 12，额外预留线宽；保留指定接口侧和位置。原有 `straight`、`elbow` 保持原行为。
- 模块或障碍物移动后重新计算路径；支持缩放父容器。界面中的连线路径菜单也能切换“自动避障”。
- 无可用通道、接口被遮挡或朝向画板外侧时，返回可操作的错误并整体撤销当前命令；Agent 可以调整接口、间距或留白后重试。手动拖动、缩放也保留上一个有效状态，不写入失败操作的撤销记录。锁定连线不能被障碍物移动间接改变。
- 搜索最多 80 个模块/独立图元（含端点），以对象包围盒作为障碍，支持最多 30,000 个网格点。默认其他连线不作为障碍；阶段 7 可显式启用 `avoidConnections`。仍须检查交叉和共线路段。

### 阶段 6：可定位的连线诊断

`check_figure` 与「文件 → 检查图稿」使用同一套浏览器几何测量，读取绑定连线实际渲染出的路径、文字与组件边界。SVG 导出和服务端渲染保留绑定端点标记，旧项目重新打开后也能检查；草稿基线按同一规则重新渲染，避免将旧 SVG 缺少标记误判为新增问题。

| 问题代码 | 检查内容 | 常用调整 |
| --- | --- | --- |
| `wire-crossing` | 两条线交叉或非共用端口接触 | 调整分支顺序、模块位置或接口 |
| `wire-overlap` | 共线重叠长度 | 判断是否有意共用分支，否则分开端口或增加间距 |
| `wire-obstacle` | 穿过组件或独立图元的边界区域 | 切换自动避障、移动模块或调整接口 |
| `wire-text` | 穿过实际文字包围框 | 移动标签或改走线路径 |

- 问题返回稳定 `key`、`ids`、`magnitude`、局部图 `region` 和 `suggestion`。Agent 可将 `region` 直接传给 `render_region`，调整后重新检查；界面的「定位」同时选中相关对象并聚焦问题区域。
- 共用同一模块同一端口的端点接触不报警；共线路段仍提示，以便确认分支清晰。绑定线允许直线、折线和自动避障生成的路径；自由曲线与位图中的连接不在范围内。
- 图形/文字穿越按包围框与路径中心线估算，空白区域及有意交叉可能触发提示，因此均为 warning。Agent 不能为消除提示而删除科学关系；保留提示时须在提交说明中披露。
- 新增/加重的提示会暂停自动应用，保留预览供用户核对。隐藏、复杂裁切或不支持的绑定路径计入未检查数量，也会暂停自动应用；手动应用仍可使用。结果随现有草稿、评审快照及任务记录保存。
- 上限为 200 条线、合计 2,000 段（每条最多 200 段）、1,000 个障碍对象、250,000 次比较；超限明确返回 `truncated`，不会当作完整通过，草稿提交仍受检查截断约束。

### 阶段 7：经过复查的连线修复

新增第 25 个工具 `repair_connections`，接受 1–12 条绑定连线的图元 ID。示例：

```json
{"requestId":"repair-1","expectedRevision":6,"ids":["ai-horizontal","ai-vertical"],"adjustPorts":false}
```

- 使用实际渲染的组件、文字和现有路径测量作比较，尝试避障、留白和避让其他线。默认保留接口侧和位置；仅 `adjustPorts: true` 才搜索其他端口侧与 25%/75% 位置，端口有特定含义时应保持默认值。
- 保留模块位置与内容、连接对象与方向、标签、样式和未选连线。选中连线必须在任务范围内且未锁定；重新排布模式允许改走线，外观模式拒绝。重绘模式仍受原范围边界限制。
- 候选方案必须减少已有连线问题，并经过整图实际渲染复查，确认没有新增/加重任何规则问题、增加未检查项或改变未选对象，才会整体应用。未改善、通道不可用或复查失败时保留原图。
- 成功修改使 revision 增加一次；未修改时版本不变。两者均保存 requestId 回执，恢复或重复请求不会再次执行。修复不代替 Agent 的观察，修改后仍须整图 `render_region` 和 `check_figure`。返回 `evidenceStale` 时需要核对并重新绑定关系证据，再进行新版本评审。
- 搜索最多 192 个候选、两轮、每条最多 32 个设置；整图最多 80 条绑定线。返回 `trials`、`unavailable`、`searchLimited`、前后问题和修改 ID。有限搜索可能找不到解，不代表该图无法修复；可调整模块位置后再试。
- 手动入口在「连线 → 尝试修复所选连线」。成功只增加一项撤销记录，未修改不污染撤销栈。计算期间若图稿、画板或 AI 任务状态变化，拒绝应用旧结果。

**持久避让其他连线**

`connection.route: "avoid"` 配合 `avoidConnections: true` 可将其他连线作为障碍；界面提供同名开关。按普通路径优先、启用此设置的路径按 ID 升序计算，形成无循环依赖，因此重新载入与不同对象存储顺序得到相同结果。共用端点模块的线不互相避让，保留分支汇合；仍由诊断提示共线问题。

最多参考 80 条其他路径、160 个线段，仍受 30,000 网格点限制。斜线采用保守包围框，可能拒绝实际存在的通道。移动参考线或模块会重算依赖路径；如果会改变已锁定线或没有可用路径，编辑整体拒绝。批量修复另有更严格的未选对象保护，不会为修复所选线而悄悄重排未选线。

## 运行记录和边界

每个任务目录保存原始 `task.json`、`draft.json`（schema 3 草稿、证据、命令回执、检查点、日志及提交结果）、最新 `draft-preview.png`，以及完成后的 `after.svg/png`。`reviews/<轮次>/` 保存固定快照、局部图、导出文件、各角色会话与报告。取消或失败不修改画板。旧 schema 2 草稿仅保留诊断，不能通过新恢复入口继续。

默认每次执行限 15 分钟、160 次工具调用；每个原任务最多 8 个检查点。规则检查可以识别越界、小文字、已知纯色背景对比度、文字包围框重叠，以及上述绑定连线问题；不能判断论文机制是否正确，也不能读取公式路径和位图内的文字。独立评审会检查论文解释，但不能替代研究者对证据与科学结论的确认。

- 单元测试覆盖命令原子性、锁定/范围、幂等、版本冲突、检查点回滚、提交前置条件及同一问题恶化。
- 浏览器测试通过真实渲染执行“插入 → 观察小字号 → 修订 → 检查 → 采纳”，验证图表、公式、绑定连接、素材元数据、撤销及重新载入。
- transport smoke 使用**真实 Codex SDK/CLI 和 stdio MCP**，但模型响应来自本地脚本服务器：验证 20 轮请求中的工具执行、流程排版和图片回传，不调用外部模型，不证明真实模型绘图质量。
- `--connections` 使用 14 轮本地脚本请求验证“发现交叉 → 局部观察 → 移动模块 → 再检查 → 提交”，断言问题 ID、裁切坐标、修复建议及最终提示消除。浏览器测试另验证提示会暂停自动应用、刷新恢复和撤销。
- `--repair` 同样使用 14 轮本地脚本请求，改由 `repair_connections` 消除交叉；断言模块位置不变、修复日志和持久避让设置。单元和浏览器测试覆盖无改动版本、恢复去重、锁定/范围、并发编辑拒绝、实际复查、撤销和重载。
- review transport smoke 使用真实 SDK/CLI 启动 8 个独立会话，完成两轮评审、阻断、修订、证据更新和提交。模型响应仍来自本地脚本服务，不验证真实模型的判断质量。
- desktop smoke 使用隐藏 Electron 窗口验证目录、MathJax、文字测量、PNG 及实际 PDF 导出后重新渲染。
- 恢复测试验证服务重启、命令去重、检查点保留、同一快照部分评审重用，以及刷新页面后的继续与采纳。
