# 案例五：让两次选择出现不同结果

**来源**：[PCTree v1](https://arxiv.org/html/2608.02123v1)，2026-08，§4.1–4.2、算法1；原图 Fig.2–3 位于 PDF p5–6。

用现有 v0.4.3 先做新论文迁移，没有先修改规则。这里容易混淆的是“下一步扩展谁”与“最终验证谁”。如果所有停扩节点都恰好落在最终预算外，两种选择即使画成两个模块，读者仍可能以为它们等价。

因此原创示例特意令 F 不属于下一 frontier，却进入最终 top-N。主树保留 F 及其祖先，底部对整个 pool 排序，右侧同 ID 矩阵表现 F 的祖先访问。这样例子本身就说明区别，额外节点不是为了显得复杂。

- 主树用外环表示实际被展开的父节点，用填色表示最终入选。这两个属性可以同时成立，不宜用一套互斥颜色覆盖。
- logits 薄片只说明共享的向量；树和矩阵保持二维。并行骨干共用，Markov 调用按深度顺序执行，同层父节点批处理但各自条件化。
- 以路径概率 exp(s) 展示排名，与原文累计对数分数排序一致。示意 k、B、N 与所有概率就近说明，不能冒充论文实验配置。
- 首稿节点分数沿树边放置，造成数字与出边重叠；修订把 ID 与分数收进节点。Markov(A,B) 改成父批次及逐父公式，降低误读为父向量融合的风险。

可迁移的是**选择能暴露差异的实例**。MEMO 的 dual、GoA 会改变边界行为的代码示例也具有这个特点。不能强行让每个算法出现反例，也不据一个构造实例推断性能提升。
