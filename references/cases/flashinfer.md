# 案例二：把“共享缓存”画成跨表示对应

**来源**：[FlashInfer](https://arxiv.org/abs/2501.01005)，v2，§2.2、§3.1.1–3.1.2、Fig.2–3。

### 旧式系统图为什么不够

“请求→缓存→kernel→结果”四个盒子无法解释共享在哪里、拆分什么、为什么需要不同块大小。

### 关键阅读发现

请求共享前缀时，访问矩阵含共同的稠密部分。通过不同索引表示共享与独有部分，无需移动原缓存。共享部分用较大的 query 行块以便复用；子计算产出 attention output 与 log-sum-exp 状态，再合并。

### 选择的画法

1. 定义最小示例：三个请求引用同两个公共页，各带一个独有页。
2. 相同页 ID 同时出现在请求序列、打乱排列的物理页和二维访问矩阵中。
3. 立体只用于 K/V 存储页；页 ID 保持水平，表面内部细线不穿过标签。
4. 拆分访问图时显示每个真实示意块的边界：`Br=3, Bc=1` 应分别框住每一列的三行，而非用一个外框把两列误编码成宽度 2。
5. 子计算中直接展示多个查询指向同一 KV tile，以及各自查询指向独有页。状态合并用 `(O, LSE)`，不画普通平均。

### 迁移边界

适合索引映射、稀疏计算、存储共享和任务调度。点表示“是否访问”，不能让颜色看起来像测量出的 attention 强度。数组重排、索引重组和物理搬移必须区分；矩阵压紧显示后仍保留页 ID，不能把新的列位置当原物理地址。
