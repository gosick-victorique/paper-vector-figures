# 案例一：把“消息传递”拆到一个节点

**来源**：[Graph-of-Agents](https://arxiv.org/abs/2604.17148)，§3.2.3、Appendix B p16；[作者实现 modules.py](https://github.com/UNITES-Lab/GoA/blob/main/modules.py) 中 `_build_reference_descriptions`、`_run_s_to_t`。查看于 2026-10-16。

### 旧图为什么不够

两张三角图加相反箭头能说明阶段，却不能说明响应如何更新。下面再写“weighted responses → prompt”依然把机制留在文字里。

### 关键阅读发现

正文公式有带权响应，附录和实现则明确：归一化权重转成 high / moderate / low 相关性标签，标签与文本响应拼入提示。目标 LLM 读问题、自己的旧回答与其他模型回答，生成新文本。不能画成数值向量加权和。

### 选择的画法

1. 全流程降为窄定位条，突出当前 Source→Target 阶段。
2. 左侧只保留目标节点及其来源，标示示例权重。
3. 中间把一条用户提示展开：问题、自身旧答案、带标签的来源回答、修订指令。相同来源 ID 和颜色从图延续到提示段。
4. 右侧显示响应变化，并用一个简单输入说明改变了什么行为。

试用的原创代码实例：判断列表元素是否均非负。旧答案用 `x > 0`，某来源提出 `x >= 0`，另一个使用 `min(xs)`；示意修订保留非负条件与空列表语义。此实例解释操作，不是模型实测结果，不据此声称模型必然改对。

### 视觉重排试验

机制已经清楚之后，再增加提示细节收益有限。后续固定同一示例，改用开放文本构图：同行回答及标签在左，自身旧答案在上，agent 居中，新答案和行为变化在右。完整提示降为底部组成索引，明确这些部分属于一条用户消息；未把 peer 文本画成数值混合。

这次改变主次与位置，不增加新的论文机制。首稿的生成箭头落在新答案下方空白，修订让它准确进入代码；移除大容器后，要用文字对象自身承担连接端点。局部图见 [开放文本构图](../design-guide.md#开放文本让变化本身成为主体)。

### 迁移边界

适合其他依靠文本上下文更新的 agent、检索和批评方法。只有原文明确支持时才画相关性标签；不能把 GoA 的阈值变成通用设计。涉及文本对象时，算术符号未必意味着直接对文本做数值运算。
