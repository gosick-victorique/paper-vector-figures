# 主绘图代理自检与迭代

这份清单用于绘图时预检；生成后的正式评审按[四位独立评委协议](jury-review.md)执行，四维评分、综合意见和改后复评不能由主代理的自评代替。

## 对实际图稿提问

1. **换标题测试**：只换模块名能否用于十篇论文？若能，缺少独特操作。
2. **解释测试**：能否指出关键对象如何变化？只能读出顺序时应展开机制。
3. **追踪测试**：选一个证据、token、节点或 patch，能否追踪来源、去向、对应？多色不等于可追踪。
4. **视线测试**：最先看到的是不是创新点？普通预处理不应比核心更大。
5. **关系测试**：能否分清数据、选择、训练约束和放大引线？
6. **密度测试**：细节回答了新问题，还是重复？主体空泛与局部拥挤可能同时发生。
7. **深度测试**：立体层次有无帮助，是否遮住比较对象或暗示虚假关系？

评分必须附具体位置、可能误解和修改，例如“E2 两线交叉，dual 去向不清；改用 T/V 两列并保持 E2 标签”。按四评委协议保留各人分数、分歧和证据，不能用单一总分掩盖方法错误。

### 将问题定位到实际对象

| 图上现象 | 需要修改的关系 |
|---|---|
| 两个融合输入横排成 A→B→结果 | 排版引入了不存在的串行转换；让两路各自接到实际融合算子，见 AdvFractal R5、CamoShift R2；后者的背景与目标裁块都来自原图 |
| reader 写 (q,T,V)，却只有 V 入边 | 标签与输入关系不一致，补齐真正输入 |
| 最大时间窗口越过数据范围 | 按可见范围重排窗口，不能固定每种尺度画相同数量 |
| 放大网格后仍要跳到远处寻找操作 | 将比较或映射放到对象附近；参见 M2Patch 案例 |
| cards 画成 timeline；复制前后词句不同 | 造型和内容没有证明声明的属性，改图或改声明 |
| 标作新增输出 U 的行仍包含旧 anchor | 保留上下文位置，但用括号明确新增集合及计数；参见 D-Loop 案例 |

只处理当前图实际出现的问题。可先看[三组前后对照](visual-entry.md#已有图稿比较修改的收益与代价)：重复对应、局部太小、汇总绕远。按同一关系比较改动收益与代价，裁图范围或显示比例不同不能当作阅读速度证据。完整依据留在[机制案例](worked-mechanisms.md)，其他变体见[设计图例](design-guide.md#同内容构图对照)。

## 快速循环

**读依据 → 选构图 → 画与自检 → 四位独立评委看图打分 → 综合决定 → 改图 → 四位复评。**

每轮优先改3–5项有据问题，必要时重构主视觉；轮次与停止条件见评审协议。持续优化时每轮有待验证假设；旧问题已处理后换机制类型或构图，不无限调整色值或追逐分数。看图不发展成文件格式验收。

## 优化 skill 的项目日志

记录：案例与依据、本轮假设、旧图问题、设计动作、图上观察、剩余不足、经验是案例专属还是已跨案例支持。

保留可比较旧稿。若每篇都变成“输入→三个等大盒子→输出”，重新审视构图选择，避免把绘图惯性写成通用模板。
