# 整图框架提示词

这些提示词控制对象、分区和阅读路径，供绘图前直接改写使用。它们是构图起点，不是论文事实或固定模板；具体造型从[组件知识库](component-recipes.md)选择，再按[空间方案探索](spatial-exploration.md)比较。已有原图案例与局部画法见[构图选择与空间细节](design-guide.md)。

## 选择与使用

先从正文提取真实关系，再按下表选候选。整图以一种框架为主，必要时借另一种组织局部，不把多个完整框架拼成许多小面板。用户提供的大体框架优先；已认可布局不必重新选型。没有合适条目时自拟框架，不强行匹配。

| 阅读任务 / 关系 | 优先考虑 | 可以比较的另一种组织 |
|---|---|---|
| 多个贡献围绕同一对象，没有需要强调的先后 | F1 共同对象与并列模块 | 主次明显时 F2 |
| 一个核心机制、一个辅助机制，共同产生更新或结果 | F2 非对称主次分区 | 都依附同一主干时 F3 |
| 创新发生在系统的某个位置 | F3 主干与局部展开 | 对象的状态变化更重要时 F4 |
| 同一对象的前后、不同方法或不同条件 | F4 对齐对照 | 条件的生成方式更重要时 F8 |
| 多个操作读取、选择或修改共享内容 | F5 共享状态与局部操作 | 独立受体仅共享输入时 F1 |
| 学习或准备过程与实际使用过程不同 | F6 训练与使用 | 差别只在一个局部时 F3 |
| 多源观测在同一空间内对应、融合或重建 | F7 共同坐标与多源观测 | 没有实际空间对应时 F1/F4 |
| 解释实验如何设置、控制什么、比较什么 | F8 实验场景与条件 | 只展示已有结果时 F4 |

将选定提示词中的占位项替换成论文对象、操作和真实依赖，删去不适用的句子，形成约一段的 `layout_prompt`，放在现有 brief 中。提示词至少让人想象出：主对象在哪里、关键模块怎样相处、哪处展开、读者先看什么。尺寸从当前任务填写，不沿用库中的隐含比例；“左/右/上/下”均可随版面调整。

简记 `框架及选择理由 / 实际 layout_prompt / 用到的组件条目` 即可，不新增长报告。两种成立组织的比较沿用主流程，不能把一个语义错误的框架作为陪衬。框架提示词不直接成为图内说明文字，也不替代读论文、空间草图或四评委评审。

## F1 共同对象与并列模块

**适用：** 多个分支、约束或贡献作用于同一对象；图要突出互补关系。共享的是输入、参数、状态还是目标，必须先区分。

> 以【共同对象】作为统一入口，将【模块 A】与【模块 B】并列组织，各区直接展示其作用的对象和关键变化。用一致的身份标记建立它们与共同对象的联系，只在真实汇合处连接【共享输出/目标】。【主要贡献】获得更大的视觉主体，普通处理压缩为接口。模块内部优先探索能显露作用范围的立体结构，读数保持正视；不以跨区长箭头串成阶段。

**保留：** 各分支的受体、独有作用及必要汇合。并列展示不表示计算并发；如果 B 必须读取 A 的输出，保留依赖或改选 F3。模块数量按论文，不固定成三块。

## F2 非对称主次分区

**适用：** 一个需要充分展开的核心机制，另有较紧凑的互补机制，两者共同驱动结果或更新。

> 采用主次明确的紧凑分区：左侧主区展示【核心机制】，围绕【核心对象】安排其必要的局部变化；右上区展示【互补机制】，右下区承接两者共同驱动的【更新/结果】。主区的内部上下关系用于解释【局部关系】，不是增加独立章节。让共同对象、选区和中间表示可追踪；仅保留必要的就近连接，容器随内容收边，不追求等高等宽。

**保留：** 主机制的结构上下文、互补机制的独有作用、共同出口的来源。只有论文确实存在共同出口时采用该关系；右下区不是固定必有的优化器。若辅助区空，调整分区或换框架，不塞装饰补齐。

## F3 主干与局部展开

**适用：** 系统架构、编码解码、检索生成或处理流程中，创新集中在少数作用位置。

> 用紧凑主干保留【输入】到【输出】的必要依赖，把【关键位置】在主干上明确定位，并在其邻近展开【核心操作】。展开区沿用该位置的对象、索引和颜色，画清进入、改变与返回；常规模块只保留身份和接口。主干提供语境，展开区承担主要解释。优先用切片、抽出局部或剖面显露内部，避免把整条主干复制一遍。

**保留：** 作用位置与返回位置的对应，真实分支、跳连或跨层联系。概览中的抽出位移只是展示动作，不是算法迁移；若机制不依附某一主干，不强造流水线。

## F4 对齐对照

**适用：** 定性结果、机制概念图、消融或同一对象状态变化。

> 将【比较条件】沿一个方向排列，将【同一对象/观察部位】沿另一方向对齐。稳定身份、裁剪、尺度和视角，仅让【需要比较的变化】成为差异。以【主要差异】形成视觉焦点，必要时共享一个局部展开或正视读数。对象有有益的内部空间关系时使用立体剖面或分层；真实图像保持可比，不为统一风格重画成图标。

**保留：** 同一对象对应、比较基准和变化位置。方法对比不是时间流程；不要顺手连接因果箭头。定量数据仍用科学绘图工具，不能用透视大小暗示数值。

## F5 共享状态与局部操作

**适用：** 记忆、缓存、图结构、检索集合、共享扰动等对象被多个操作访问。

> 把【共享状态】画一次作为主体，让【读取/评分】、【选择】和【写入/更新】靠近实际访问的局部。通过稳定索引追踪一个代表项，在主体上显露它发生了什么变化；全体更新与局部写入分别可见。用槽位、分层索引或局部剖面探索空间表达。重复引用使用同名接口，避免多份副本看起来像多个独立状态。

**保留：** 哪些内容共享、谁读谁写、选择依据与作用范围。不存在写入的普通共享输入无需画成存储系统；几何邻近不能替代真实图边或检索关系。

## F6 训练与使用

**适用：** 训练、离线准备、适配与实际推理之间存在重要结构差异。

> 将【训练/准备】与【使用/推理】组织成清楚的两区，前者只展开【学习到或构建的对象】如何得到，后者突出它如何用于【实际任务】。交接处明确传递的是【权重/索引/数据/其他产物】，复用同一身份标记。仅训练时存在的监督与辅助分支留在训练区；两区的公共结构可简写，面积按当前图的重点分配。

**保留：** 真实交接产物、使用期输入以及可变/固定对象。冻结参数不等于阻断输入梯度；不能把训练样本画成部署输入。单阶段方法不为好看而拆成两阶段。

## F7 共同坐标与多源观测

**适用：** 多视图、几何对应、空间融合、重建或传感器关系。

> 以【共同空间/对象】作为中心，在周围安排【观测来源】及其实际对应区域。挑选一个可追踪的位置，展示它在【各视图/表示】中的对应与【融合/重建】发生处。用有依据的视锥、截面或局部体素显露关系，重要比较读数放在正视面。只画解释当前对应所需的射线，减少遮挡和交叉。

**保留：** 坐标含义、来源身份、对应点与聚合位置。没有相机或真实几何的多分支网络不套用视锥；展示用的投影不声称是论文的相机参数。

## F8 实验场景与条件

**适用：** 实验设置、威胁模型、评价协议，需要理解谁能访问或改变什么。

> 用【实验场景/研究对象】建立语境，在其邻近展示【可控因素】如何作用，以及【观测量】从哪里获得。将【对照条件】紧凑并列，共用相同基准对象。通过边界、作用区域和少量必要连接说明【访问/修改范围】，将配置参数留给图注。场景和空间布置服务于实验关系，不挤占控制与测量的说明。

**保留：** 控制、观测、对照与可见/可修改范围。实验设置不是效果证据；未运行实验不能绘制貌似真实的成功结果。只比较结果时使用 F4。

## 组合示例：从泛称改为可执行提示

“三块、三维、漂亮”没有指定关系。若正文确实说明两个目标共同更新一个输入，可以写：

> 以被修改的输入为共同对象，将条件响应与特征响应并列呈现；条件响应占主区，显露其在网络内部的作用位置，特征响应在邻区以同一对象的特征对照解释。共同更新靠近两区交接处，展开空间域处理与频域筛选的衔接。使用一致选区和身份标记保持对应，短连接汇入同一更新对象。各区按内容收紧，保留结构上下文，公式和次要参数交给正文。

这里借用了 F2，局部借用 F3，并可调用 C3、C8、C10、C11。这只适用于具有这些机制的论文；不能因示例存在就为别的论文添加频域处理。
